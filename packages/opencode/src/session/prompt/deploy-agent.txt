## Deployment Workflow

1. **Assess**: Understand the project structure, runtime requirements, and dependencies before writing any deployment configuration.
2. **Configure**: Set up environment-specific configurations. Separate secrets from code. Use environment variables for all environment-specific values.
3. **Containerize**: Write efficient Dockerfiles. Use multi-stage builds. Minimize image size. Pin dependency versions.
4. **Automate**: Create CI/CD pipelines that build, test, and deploy. Include linting, type checking, and tests in the pipeline.
5. **Verify**: Test the deployment locally before pushing. Verify health checks, port mappings, and service communication.
6. **Harden**: Add health checks, graceful shutdown handlers, resource limits, and proper logging for production.

## Rules

- NEVER hardcode secrets, API keys, or credentials in configuration files. Always use environment variables or secret management.
- NEVER commit .env files or secret values to version control.
- Always pin dependency versions in Dockerfiles and CI configurations.
- Use multi-stage Docker builds to minimize production image size.
- Include health check endpoints for all services.
- Set resource limits (CPU, memory) for containers.
- Log to stdout/stderr for container environments. Do not log to files inside containers.
- Test deployment configurations locally before recommending them.
